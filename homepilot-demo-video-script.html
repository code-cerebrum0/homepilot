Scene-by-scene script

1 Hook — what problem this solves 0:00 – 0:30

"Your home uses electricity 24 hours a day, but most people have no idea what's happening — which device is drawing power right now, how today compares to yesterday, or what it's actually costing them."

"HomePilot is a self-hosted energy assistant that answers those questions — and it does it through a real MCP server, so any AI client that speaks the Model Context Protocol can connect to it."

Screen: Show the frontend dashboard loading — devices, power reading, cost card all visible at once.
2 Live dashboard walkthrough 0:30 – 1:00

"The dashboard shows real-time power draw, today's kilowatt-hours, month-to-date cost based on a configurable tariff, a 7-day trend chart, and a per-device breakdown."

"The data comes from devices posting readings to the API — smart plugs, Home Assistant, simulated sensors for demo purposes."

Screen: Scroll through dashboard — point at the cost card, the daily chart, the device list. If simulator is on, show a reading arriving live.
Tip: Run the server with SIMULATOR_ENABLED=true so readings update during the recording without needing real hardware.
3 AI chat — MCP in action 1:00 – 1:45

"Now here's where the MCP server matters. When I type a question to the built-in assistant, it doesn't call the database directly — it routes through the same MCP dispatcher that an external client like Claude would use."

"Watch what happens in the response."

Screen: Open chat, type: "How much power am I using right now and what did I use yesterday?" — wait for reply.

"The answer came from real data. But look at the API response — there's an mcp_calls array. It shows that the server made a tools/list call and two tools/call calls, all using protocol version 2026-07-28. That proves the MCP code path ran — not a shortcut."

Screen: Open browser DevTools → Network → find the /api/v1/households/.../chat response. Expand mcp_calls in the JSON.
Screen: Also show the response header X-MCP-Calls: 3 in the headers panel.
4 Code tour — the MCP server 1:45 – 2:30

"Let me show you what's actually under the hood. This MCP server uses no SDK at all — no fastmcp, no modelcontextprotocol package. It's implemented directly against the spec in two files."

Open: backend/requirements.txt — point at the 13 lines, none of which say mcp or fastmcp.

"First, dispatch.py. This is the JSON-RPC dispatcher. It supports both the modern 2026-07-28 era and legacy 2025-11-25. The era is detected from the _meta field or the MCP-Protocol-Version header."

Open: backend/app/mcp/dispatch.py lines 28–36 — show MCP_PATH, PROTO_MODERN, SUPPORTED_VERSIONS. Then scroll to lines 144–160 — show the modern-era method dispatch switch.

"Second, tools.py. Each tool is a dataclass with a name, a JSON Schema for input validation, a handler that queries the database, and a text renderer for voice-friendly output. Six tools in total, all read-only."

Open: backend/app/mcp/tools.py lines 44–66 — show McpTool dataclass and mcp_spec(). Then scroll to lines 338–352 — show the TOOLS registry.

"The HTTP endpoint lives in mcp.py. It handles Origin validation, Bearer token auth, body size limits, era detection, and all four required modern-era headers — MCP-Protocol-Version, Mcp-Method, Mcp-Name — before a single tool runs."

Open: backend/app/routers/mcp.py lines 102–106 — show the route. Then lines 172–214 — show the header validation block.
5 OAuth 2.1 flow — live demo 2:30 – 3:15

"The MCP spec requires OAuth 2.1 for remote servers. HomePilot ships its own authorization server — the full authorization code flow with PKCE, refresh rotation, token revocation, and RFC 9728 discovery documents. No third-party auth service needed."

Screen: Open http://localhost:8000/.well-known/oauth-protected-resource in the browser — show the JSON response with resource, authorization_servers, scopes_supported.
Screen: Open http://localhost:8000/.well-known/oauth-authorization-server — show authorization_endpoint, token_endpoint, code_challenge_methods_supported: ["S256"].

"Any MCP client that follows the spec will hit these discovery endpoints first, find the authorization server, and start the PKCE flow automatically."

Open: backend/app/routers/oauth.py lines 149–160 — show protected_resource_metadata(). Then lines 195–244 — briefly show PKCE validation in _validate_authorize_params.
6 MCP Inspector — external client connects 3:15 – 3:45

"To prove this is a real, externally-connectable MCP server and not just an internal helper, I'll connect the official MCP Inspector — a tool from Anthropic — to it right now."

Screen: Run npx @modelcontextprotocol/inspector in terminal. Set Transport to Streamable HTTP, URL to http://localhost:8000/mcp/v1. Click Connect.
Screen: The browser opens the HomePilot login page at /oauth/authorize. Sign in. Inspector receives the token and loads the Tools tab.

"Six tools appear — get_current_usage, get_daily_usage, compare_energy_usage, and so on. I'll call one live."

Screen: Click get_current_usage → Run Tool. Show the structured JSON response with current_power_w, today_kwh_so_far, freshness.

"That's a real MCP tools/call over Streamable HTTP, authenticated with OAuth 2.1, returning live household data. No SDK. All spec-compliant."

7 Wrap-up 3:45 – 4:00

"HomePilot is a full-stack energy monitoring platform with a self-hosted MCP server built directly on the spec — no SDK, dual protocol era support, complete OAuth 2.1, and 50 passing tests. The link to the repo is in the description."

Screen: Show the terminal with pytest tests/ -v output — 50 passed.

MySQL seed data

Run this against your homepilot database after the server has started (tables are auto-created on first boot). Replace the Argon2 hash below with a real one or register via the API instead.

-- ───────────────────────────────────────────────────────────────────────────── -- HomePilot demo seed data -- Run: mysql -u homepilot -p homepilot < seed.sql -- ───────────────────────────────────────────────────────────────────────────── -- 1. User (password = Demo@password1 — generate real hash via the /auth/register API) INSERT INTO users (name, email, password_hash, created_at) VALUES ('Demo User', 'demo@homepilot.local', 'REPLACE_WITH_ARGON2_HASH', NOW()); -- 2. Household INSERT INTO households (name, created_at) VALUES ('Demo Home', NOW()); -- 3. Membership (owner role) INSERT INTO memberships (user_id, household_id, role) VALUES (1, 1, 'owner'); -- 4. Tariff (flat ₹8/kWh, 18% GST) INSERT INTO tariffs (household_id, name, currency, type, flat_rate_per_kwh, fixed_monthly_charge, tax_percent) VALUES (1, 'Home Tariff', 'INR', 'flat', 8.0, 150.0, 18.0); -- 5. Devices INSERT INTO devices (household_id, name, source, status, secret_hash, created_at) VALUES (1, 'Air Conditioner', 'simulated', 'active', 'demo-secret-hash-1', NOW()), (1, 'Refrigerator', 'simulated', 'active', 'demo-secret-hash-2', NOW()), (1, 'Water Heater', 'simulated', 'active', 'demo-secret-hash-3', NOW()), (1, 'Washing Machine', 'simulated', 'active', 'demo-secret-hash-4', NOW()), (1, 'Lighting', 'simulated', 'active', 'demo-secret-hash-5', NOW()); -- 6. Readings — 30 days of hourly simulated data (device_id 1 = AC, highest draw) -- Generates ~720 rows per device = 3600 rows total. Adjust the date range as needed. INSERT INTO readings (device_id, measured_at, ingested_at, power_w, energy_kwh, interval_seconds, is_simulated) WITH RECURSIVE ts (t) AS ( SELECT DATE_SUB(NOW(), INTERVAL 30 DAY) UNION ALL SELECT t + INTERVAL 1 HOUR FROM ts WHERE t < NOW() ) SELECT d.id AS device_id, ts.t AS measured_at, NOW() AS ingested_at, CASE d.id WHEN 1 THEN 1400 + (RAND() * 300) -- AC: 1400–1700 W WHEN 2 THEN 120 + (RAND() * 30) -- Fridge: 120–150 W WHEN 3 THEN 2000 + (RAND() * 500) -- Water heater: 2000–2500 W WHEN 4 THEN 400 + (RAND() * 100) -- Washing machine: 400–500 W ELSE 60 + (RAND() * 40) -- Lighting: 60–100 W END AS power_w, CASE d.id WHEN 1 THEN (1400 + (RAND() * 300)) / 1000 WHEN 2 THEN ( 120 + (RAND() * 30)) / 1000 WHEN 3 THEN (2000 + (RAND() * 500)) / 1000 WHEN 4 THEN ( 400 + (RAND() * 100)) / 1000 ELSE ( 60 + (RAND() * 40)) / 1000 END AS energy_kwh, 3600 AS interval_seconds, 1 AS is_simulated FROM ts CROSS JOIN devices d WHERE d.household_id = 1; -- 7. OAuth client for MCP Inspector INSERT INTO oauth_clients (id, name, secret_hash, redirect_uris, is_public, created_at) VALUES ('mcp-inspector', 'MCP Inspector', NULL, JSON_ARRAY('https://inspector.modelcontextprotocol.io/callback'), 1, NOW());

Note on the user password: Don't insert a raw Argon2 hash manually — it's easier to register via the API first (POST /api/v1/auth/register), which creates the user + household + membership automatically, then run only the tariff, devices, and readings inserts above with the correct IDs.
